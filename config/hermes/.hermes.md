## Vikunja (taakbeheer)
Self-hosted op `__BOOTSTRAP_VIKUNJA_HOST__`.
De Vikunja API gebruikt non-standaard HTTP-methoden — curl en directe API-calls werken niet.
Bij elk Vikunja-verzoek: gebruik de terminal tool en voer het script direct uit. Nooit antwoorden vanuit geheugen of context — altijd live via het script. Nooit beschrijven wat je gaat doen.

```
bash ~/.hermes/scripts/vikunja.sh projects
bash ~/.hermes/scripts/vikunja.sh tasks <project_id>
bash ~/.hermes/scripts/vikunja.sh create <project_id> <titel> [beschrijving] [due YYYY-MM-DD]
bash ~/.hermes/scripts/vikunja.sh done <task_id>
bash ~/.hermes/scripts/vikunja.sh delete <task_id>
```

## Obsidian werkruimte
Vault: `/mnt/c/Users/__BOOTSTRAP_WINDOWS_USER__/__BOOTSTRAP_OBSIDIAN_VAULT_SUBDIR__`

Mappen (gebruik altijd de exacte naam inclusief numeriek prefix — `inbox/` bestaat niet, `00-inbox/` wel):

| Map | Exacte naam | Toegang |
|---|---|---|
| Inbox (AI output) | `00-inbox/` | Schrijven |
| Klanten | `01-clients/` | Lezen |
| Projecten | `02-projects/` | Lezen |
| Architectuur | `03-architecture/` | Lezen |
| Onderzoek | `04-research/` | Lezen |
| Templates | `05-templates/` | Lezen |
| Memory | `06-ai-memory/` | Schrijven |
| Playbooks | `08-playbooks/` | Lezen |

Regels:
- Schrijf AI-output altijd naar `00-inbox/` — nooit direct naar andere mappen
- Nooit bestanden verwijderen of overschrijven
- Nooit `.obsidian/`, `.git/`, `.secrets/`, `.private/` aanraken

Workflow voor nieuwe documenten — verplichte volgorde:
1. Lees relevante project/klantnotities uit de vault
2. **Verplicht**: lees eerst de toepasselijke template: `cat "/mnt/c/Users/__BOOTSTRAP_WINDOWS_USER__/__BOOTSTRAP_OBSIDIAN_VAULT_SUBDIR__/05-templates/<naam>.md"`
3. Schrijf het draft naar `00-inbox/` via de **terminal** tool (niet `process`, dat is voor achtergrondprocessen):

```bash
cat > "/mnt/c/Users/__BOOTSTRAP_WINDOWS_USER__/__BOOTSTRAP_OBSIDIAN_VAULT_SUBDIR__/00-inbox/YYYY-MM-DD-naam.md" << 'MDEOF'
# Titel
inhoud
MDEOF
```

4. Gebruiker beoordeelt en promoot naar de juiste map.
